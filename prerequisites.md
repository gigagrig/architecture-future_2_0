# Ресурсы, зависимости и доступы

Инфраструктура использует Yandex Cloud и GitHub Actions. Перед развёртыванием необходимо определить каталог, зону, сеть, квоты и бюджет каждой среды. Секреты хранятся вне репозитория.

## Рабочая среда

| Назначение | Инструменты | Документация |
| --- | --- | --- |
| Виртуальные машины | Terraform 1.11.4, Yandex provider 0.140.1 | [Модуль и окружения](Task1Advanced/README.md) |
| Состояние и автоматизация | Object Storage, YDB Document API, GitHub Actions; Python 3.10+, cryptography, boto3, GnuPG | [Подготовка и эксплуатация CI/CD](Task2Advanced/README.md) |
| Архитектура C4 | diagrams.net / draw.io; SVG для просмотра в Markdown | [Архитектурные схемы](Task3Advanced/README.md) |
| Доменные схемы | Mermaid CLI 11.4.2 и Chromium для экспорта | [Домены и интеграции](Task4Advanced/README.md) |
| Контракты событий | Валидатор JSON Schema Draft 2020-12 с проверкой format, например Ajv 8.17.1 и ajv-formats 3.0.1 | [Каталог событий](Task4Advanced/events.md) |
| Экономическая модель | Node.js 20+; внешние пакеты не нужны | [TCO](Task5Advanced/tco-analysis.md) |

Для просмотра сохранённых SVG редакторы схем не нужны. Для работы с кодом нужны Git и редактор; для загрузки CLI и провайдеров — сетевой доступ к источникам пакетов или настроенное зеркало. Версии Terraform и провайдера фиксируются конфигурацией и `.terraform.lock.hcl`; обновление требует проверки совместимости backend и модуля.

## Вычислительная инфраструктура

- Каталог Yandex Cloud с активным биллингом и квотами на ВМ, vCPU, память и диски.
- Зона, фиксированный образ ОС с cloud-init, платформа и размеры ресурсов для dev, stage и prod.
- Существующая подсеть и группы безопасности в той же зоне, что ВМ и диски.
- Сервисный аккаунт управления инфраструктурой; его ключ не прикрепляется к ВМ.
- Публичный SSH-ключ, имя пользователя и маршрут через VPN или bastion. Приватный SSH-ключ нужен только для входа и не передаётся Terraform.

Модуль получает идентификатор готовой подсети. Начальные размеры ресурсов задаются в `.tfvars`; их необходимо соотнести с образом, нагрузкой и бюджетом. Состояние локальных корней окружений хранится на машине запуска, поэтому совместное управление должно использовать корень с удалённым backend. Одной ВМ должен управлять только один state.

## Удалённое состояние

Yandex Object Storage хранит state, YDB Serverless с Document API обеспечивает блокировку. Bucket и таблица блокировок создаются до `terraform init` и имеют отдельный жизненный цикл от ВМ. Terraform фиксирован на 1.11.4 до выбора замены механизма блокировки.

- Для каждой среды используется собственный ключ `future-2-0/<environment>/terraform.tfstate`.
- Для разграничения прав сред необходимы отдельные backend, сервисные аккаунты и GitHub Environments. Разные ключи в одном bucket разделяют файлы, но не права.
- Статический ключ backend-аккаунта предоставляет доступ к Object Storage и YDB; авторизованный ключ deployment-аккаунта — к Compute Cloud.
- Версионирование bucket помогает восстановить сохранённые версии state. Аварийный state после отказа записи требует отдельного зашифрованного экспорта.

Параметры первоначального создания, права и восстановление описаны в [инструкции CI/CD](Task2Advanced/README.md). Скрипт bootstrap подготавливает dev; остальные среды требуют отдельных настроек.

## GitHub Actions

Нужны права настройки workflow, GitHub Environments, Secrets и Variables, а также runner с доступом к API Yandex Cloud и источникам провайдеров. Workflow находятся в `.github/workflows`.

Проверки кода выполняются при push и pull request. Облачные операции запускаются вручную и требуют включённой переменной `CLOUD_MVP_ENABLED`. Для apply/destroy передаётся подтверждение имени среды. Настройка включает три секрета облачного доступа, несекретные параметры ресурсов и публичный GPG-ключ для шифрования аварийного архива. Приватный GPG-ключ хранится у владельца восстановления.

## Хранение конфигурации

В репозитории допустимы имена ресурсов, несекретные идентификаторы и названия секретов CI/CD. Значения токенов, приватных ключей, паролей, локальные state и plan хранятся вне Git. Примеры `.tfvars` содержат только несекретные параметры; локальные настройки должны соответствовать исключениям `.gitignore`.
