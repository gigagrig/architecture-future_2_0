# Расширенный технический радар

Предварительная версия. Статусы обозначают предлагаемую политику выбора, а не факт промышленного внедрения. Adopt — использовать как согласуемый стандарт; Trial — ограниченный пилот с критериями выхода; Assess — исследовать без обязательства внедрения; Hold — не расширять применение, сохранять только при необходимости совместимости. ## Паттерны и способы работы

| Позиция | Статус | Применение и основание | Критерий / ограничение |
| --- | --- | --- | --- |
| Domain-Driven Design | Adopt | Границы правил, владельцев и транзакций | Контексты подтверждены доменными экспертами |
| Data Mesh | Trial | Домены владеют продуктами; платформа предоставляет общие инструменты | Два продукта с владельцами, контрактами, поддержкой и пользователями к M6 |
| Event-Driven Architecture | Trial | Междоменные факты и потоковые проекции | Replay и дубликаты не меняют финансовые итоги |
| Transactional outbox + idempotent consumer | Adopt | Согласовать локальную запись и публикацию, переносить повторы | Проверены сбои между commit и публикацией |
| Self-service BI | Trial | Каталог, конструктор и запросы по полномочиям | Портал принят пользователями к M12; запреты данных проверены |
| Версионируемые data contracts | Adopt | Совместимость событий и витрин | Несовместимое изменение блокируется до согласования миграции |
| Федеративное управление данными | Adopt | Общие правила доступа/качества, ответственность у доменов | Поля и владелец определены для каждого продукта |
| Strangler + антикоррупционные адаптеры | Adopt | Постепенная замена функций DWH/Camel | Один writer на агрегат; выполнена репетиция отката |
| Разделение команд и аналитических проекций | Adopt | Операционная запись не зависит от доступности BI | Витрина не подтверждает финансовую операцию |
| Event sourcing всех доменов | Hold | Полная перестройка хранения не нужна для событийной интеграции | Возвращаться к оценке только при конкретной потребности аудита |
| Общая БД для новых доменов | Hold | Сохраняет связанность и общий цикл изменений | Новая бизнес-логика не добавляется в DWH |

## Технологии и инструменты

| Managed Service for Apache Kafka | Trial | Раздельные операционные и аналитические потоки | Проверить ACL, lag, пропускную способность и восстановление |
| Kafka Streams | Trial | Доменные потоковые проекции без отдельного вычислительного кластера | Подтвердить state recovery и идемпотентную запись |
| Managed Service for ClickHouse | Trial | Изолированные доменные витрины | Проверить типовые запросы, версии записей, доступ по ролям |
| Managed PostgreSQL | Trial | Метаданные портала и доменные транзакционные хранилища | Проверить резервные копии и изоляцию доменов |
| Apicurio Registry | Trial | Реестр схем Kafka | Проверить выбранный формат и правила совместимости |
| OpenMetadata | Trial | Каталог, владельцы, происхождение, качество | Проверить нужные коннекторы, поиск, права и стоимость эксплуатации |
| Java / Spring Boot | Adopt | API портала, совместимость с компетенциями финтеха | TODO: подтвердить наличие команды; базовая технология не равна готовому сервису |
| Python и Go | Adopt | Существующие ИИ и финтех-сервисы | Сохранить доменные реализации и общие контракты |
| TypeScript / React | Trial | Web-портал и конструктор отчётов | UX-пилот с пользователями, проверка доступа и экспорта |
| Корпоративный OIDC IdP | Adopt | Вход сотрудников и группы | Конкретный продукт не задан; интеграцию и отзыв прав проверить |
| OpenTelemetry + Prometheus/Grafana | Trial | Метрики, трассы, алерты и представление состояния | Развести технические метрики и защищённый аудит, проверить redaction |
| Terraform + Yandex provider | Trial | Воспроизводимые окружения | Локальная валидация есть; реальные apply и lifecycle ещё не проверены |
| GitHub Actions | Trial | Ручной запуск инфраструктурных изменений, отдельные проверки push/PR | Проверить настройки Environments и облачный lifecycle; шифрованный аварийный экспорт предусмотрен |
| YDB Document API locks | Hold | Временная совместимость state для фиксированной версии Terraform | Выбрать замену перед обновлением CLI; не расширять на новые контуры |
| Kubernetes | Assess | Стандарт размещения при росте числа сервисов | Нужен расчёт выгоды и готовность эксплуатации; для пилота достаточно ВМ |
| Apache Flink | Assess | Сложные окна/большой state при подтверждённой необходимости | Внедрять, только если Kafka Streams не удовлетворяет измеренным требованиям |
| Power BI | Hold | Существующие проверенные отчёты на период перехода | Не наращивать зависимость от DWH; возможен клиент согласованных витрин |
| SQL Server 2008 / PowerBuilder | Hold | Legacy до переноса операций и архива | Отключить по критериям миграции, не выполнять бессогласованный big bang |
| Apache Camel как центральная ESB | Hold | Антикоррупционные адаптеры на время миграции | Удалить с критического пути к M36; сам Camel не запрещён как библиотека |

Слой данных состоит из доменных транзакционных БД, контрактных событий, обработчиков, витрин и разрешённых архивов. Портал работает только с каталогом и витринами. Медицинский ИИ имеет отдельный закрытый контур, не используется как источник содержимого для BI. Это соответствует [целевой архитектуре](../Task3Advanced/architecture.md).

## Основания выбора

Принципы Data Mesh: [доменное владение, продуктовый подход, платформа и общие правила](https://martinfowler.com/articles/data-mesh-principles.html). Выбор Kafka и ClickHouse как кандидатов учитывает наличие соответствующих управляемых сервисов в одобренном облаке: [Kafka](https://yandex.cloud/en/docs/managed-kafka/) и [ClickHouse](https://yandex.cloud/en/docs/managed-clickhouse/). Это не подтверждение пригодности для фактических объёмов: sizing и нагрузочные проверки остаются TODO.
